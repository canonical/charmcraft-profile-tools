This repo contains the latest [Kubernetes](kubernetes) and [machine](machine) charms that `charmcraft init` generates, using Charmcraft from `main`. This repo also provides tools for maintaining the templates in the Charmcraft source.

The tools are primarily intended to be used by the Charm Tech team at Canonical.

Here's the end-to-end maintenance process.

### Prerequisites

- A fork of the [Charmcraft repo](https://github.com/canonical/charmcraft) and a local clone
- A fork of this repo and a local clone

### Update the templates in the Charmcraft source

In your Charmcraft clone, check out a new branch, then edit the .j2 template files with your changes to the `kubernetes` and `machine` profiles. The .j2 files are located in these directories:

- `charmcraft/templates/init-kubernetes`
- `charmcraft/templates/init-machine`

Don't commit changes yet. Wait until you've tested the charms that `charmcraft init` generates.

> [!IMPORTANT]
> Don't edit the `uv.lock.j2` files. The tools run `uv lock` in the generated charms and update the `uv.lock.j2` files accordingly. When you run the tools, you can provide `uv lock` options if needed.

### Generate charms from Charmcraft and run tests

1. Run `export CHARMCRAFT_DIR="$PWD"` at the root of your Charmcraft clone.

2. Change to your charmcraft-profile-tools clone, then check out a new branch.

3. Run `just kubernetes` and `just machine`. If `just` isn't installed, use `uvx --from rust-just just` instead.

Each `just` command generates a charm using `charmcraft init`, locks the charm's dependencies, then runs `tox -e lint,unit` in the charm. If the tests fail, fix the .j2 files and run the `just` command again.

### Bump dependencies in the lockfile templates

`just kubernetes` and `just machine` run `uv lock` in the generated charms and update the `uv.lock.j2` files accordingly. This picks up any dependency changes you made in the `pyproject.toml.j2` files.

To bump a dependency that's only constrained in the lockfile, provide `uv lock` options. For example:

```text
just kubernetes --upgrade-package pytest
just machine --upgrade-package pytest
```

### Generate a Kubernetes charm that passes integration tests

The charm generated by `charmcraft init --profile kubernetes` doesn't pass integration tests.

To generate a charm that passes integration tests, run `just kubernetes-extra` in your charmcraft-profile-tools clone. This command creates a [copy of the Kubernetes charm](kubernetes-extra) and replaces its placeholder configuration/code.

`just kubernetes-extra` runs `tox -e lint,unit` after generating the charm. If the tests fail, edit [.implement/kubernetes-extra.py](.implement/kubernetes-extra.py) to change how the placeholders are replaced. Ask [@dwilding](https://github.com/dwilding/) for help if you're stuck.

### Open a PR to run integration tests and sync this repo

Commit changes in your charmcraft-profile-tools clone, then push your branch and open a PR. For example, see [charmcraft-profile-tools#53](https://github.com/canonical/charmcraft-profile-tools/pull/53).

Leave your PR in draft status. This indicates that your branch is ahead of the charms that can be generated using Charmcraft from `main`.

### Open a Charmcraft PR

1. After your charmcraft-profile-tools PR has passed all automated checks, commit changes in your Charmcraft clone. Use a conventional commit type **for each commit**. For example, `chore(templates):`.

2. Push your branch and open a Charmcraft PR. For example, see TODO.

3. Mention your Charmcraft PR in the description of your charmcraft-profile-tools PR.

4. Ask someone else from Charm Tech to approve both PRs.

### Finish syncing this repo

After your Charmcraft PR has merged, move your charmcraft-profile-tools PR out of draft status, then merge it.

### Update the Ops docs and example charms

1. Go to the [Charmcraft main branch](https://github.com/canonical/charmcraft/tree/main) and grab the hash of the latest commit that updates the profiles (which is probably the commit that came from your merged PR).

2. In the Ops source, search for `uvx git+https://github.com/canonical/charmcraft@`. Then update all instances to use the latest commit hash.

3. Make sure that the Ops tutorials and example charms are consistent with your profile changes.

4. Open an Ops PR in the normal way.
